One suggestion, one decision

Tab accepts the entire displayed suggestion immediately. Esc dismisses the entire suggestion. For a sentence edit, gray context stays untouched; for an empty body, the whole draft is inserted. No partial acceptance, no Shift+Tab acceptance, and no animation. Moving the caret within the same sentence leaves the preview anchored to those lines.

What the implementation would need

Keep Thunderbird’s HTML editor as the source of truth. Render suggestions outside the editable body, map the active sentence to a DOM range, and apply only an accepted range. Preserve links, emphasis, lists, images, signatures and quoted replies. Replacing the current renderer alone is insufficient: acceptance, undo and ⌘K also need rich-text-safe operations.

These are visual proposals, not a working HTML-compose implementation. The bubbles are shown in unobstructed states; production positioning must handle wrapping, scrolling, viewport edges and IME composition. Earlier keyboard treatments are historical explorations. The latest direction uses Tab for whole-suggestion acceptance and Esc for whole-suggestion dismissal; Shift+Tab acceptance is removed. Context cues must be grounded in actual message content.

Current-state evidence: compose/modules/diff.js (_renderDiffsToFragment, _applyFragmentToEditor), dom.js (setEditorPlainText), caret.js, config.js, and theme/palette/palette.build.js. The repository’s welcome image corroborates inline green suggestions, but predates the current newline-marker styling.

Platform references: Thunderbird HTML composition · Compose scripts · Range positioning · Non-destructive range highlights. The last option needs validation in the target Thunderbird editor.
