- `summaryGenerator.js` sends `recipient_status: "cc"` on the summary system message ONLY on positive evidence: one of the **receiving account's** addresses (account email + that account's identities, via `messageHeader.folder.accountId` → `browser.accounts.get`) is literally in `messageHeader.ccList` — AND not in `recipients` (To) AND the user is not the `author`. User in neither To nor Cc (alias/Bcc/list delivery) → field **omitted**; never claim cc when unsure (the SMTP envelope is discarded at delivery, so not-in-To proves nothing). Matching asymmetry: suppress checks (author/To) strip plus-tags (loose); the Cc claim is strict exact-address. Address extraction is GLOBAL per entry (`_extractAllEmails`) — a first-match parse drops addresses behind bracketed display names like `"Support <noreply>" <me@x>`. Scoped to the receiving account — NOT all registered accounts. Backend injects an explicit "only Cc'd" synthesized message on `"cc"`. Logic: `senderFilter.classifyRecipientStatus(toField, ccField, fromField, userEmails)` (pure) + `computeRecipientStatus(messageHeader)`. Verification log: `[SummaryGen] recipient_status for <key>: … (field SENT/omitted)`. iOS mirrors in `PromptVariables.classifyRecipientStatus` (ADR-IOS-008 parity — TB is reference). Tests: `test/senderFilter.test.js`, `test/summaryGenerator.test.js`.
