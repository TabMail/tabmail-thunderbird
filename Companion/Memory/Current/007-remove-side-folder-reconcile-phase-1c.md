- **Implemented the evidence-triggered per-folder count-invariant reconcile** (chosen direction from the 2026-07-01 entry). `_runFolderReconcile` in `fts/incrementalIndexer.js` runs after the cursor scan in `runPostInitReconcile`: per folder, `countMsgIdRange(P, P[:-1]+";")` vs `getTotalMessages(false)`; mismatch → folder-scoped set diff (stale: `listMsgIdRange` → `probeMessageIds` msgDB hash probe → ADR-017 recheck → removeBatch+verify; missing: `listKeysAboveKey`/`getMessageInfosForKeys` → `filterNewMessages` → `_enqueueNewFromInfo`); clean pass → memo pair in `fts_folder_recon_memo` (memo hit = one count RPC, zero work). Orphaned-prefix sweep only on `totalAll > Σ` evidence AND all-folders-counted; keys checked against both the experiment folder list and an `accounts.list(true)` walk before the per-key recheck.
- **Native range RPCs** (`tabmail-native-fts` 0.10.0): `countMsgIdRange`/`listMsgIdRange` — reader-thread, unsharded `message_ids` PK range scans, no schema change, no host-side msgId parsing. Feature-detected once per session (`countMsgIdRange("", "￿")` probe); old helpers → phase no-ops with a single `folder_recon unsupported` event.
- **Gotchas encoded in the implementation:** (a) headerMessageIds in the stale direction are extracted by PREFIX STRIP, not `parseUniqueId` — every key in the half-open folder range provably starts with the prefix, and parseUniqueId mis-splits folder paths containing ':' (which would have produced a wrong headerID → recheck absent → false removal). (b) `recheck_error` blocks the folder's memo write (per-folder retry is cheap; contrast with the watermark's advance-past-recheck-errors rule). (c) The orphan sweep is skipped whenever ANY folder was skipped before counting — an uncounted folder makes `totalAll > totalKnown` vacuously true and would fire full-keyspace walks without evidence. (d) `probeMessageIds` treats a per-id `getMsgHdrForMessageID` throw as NOT-missing (uncertain ≠ candidate). (e) The `"../../agent/modules/utils.js"` dynamic imports inside `processPendingUpdates`/`queueMessageUpdate` resolve fine in TB (URL normalization clamps at the extension root) but CANNOT be vi.mock'ed on the filesystem — the drain-empty re-run wiring is therefore pinned by a source-contract test instead of driving the real drain loop.
