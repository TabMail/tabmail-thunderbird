# BYOK model picker: Recommended (catalog) + All models (from your API key) (live)

- **Backend now accepts ANY well-formed BYOK model id** — the `/byok/models` catalog is just the recommended subset, not an allow-list. `config/modules/byokSettings.js populateModelSelect(tier, provider, log)` renders the `<select>` as two `<optgroup>`s: **Recommended** (catalog, order preserved — first = default, cheapest-first for Light) rendered immediately, then **All models (from your API key)** (live `/v1/models` via the existing `listByokModels()` the connectivity smoke already used) rendered once that fetch resolves — progressive enhancement, not a fallback: no saved key or a failed fetch just leaves the picker Recommended-only, and the failure is always `log(..., "warn")`'d, never swallowed.
- **Dedupe** — a live id already represented by a Recommended entry (exact match, or a dated variant like `claude-haiku-4-5-20251001` of a dateless catalog id `claude-haiku-4-5`) is excluded from the live group via `byokStorage.isModelAvailable()`'s existing matching semantics; repeated ids WITHIN the live list are also deduped (seen-Set, iOS parity) (`dedupeLiveModels`, pure, in `_testExports`).
- **Selection rule (`computeModelGroups`, pure — audited 2026-07-08, iOS semantic)**: **NEVER overwrite a non-empty saved model.** A set model is always kept as the selection even when it's in neither group (transient live-fetch failure, retired catalog id — "absent from one fetch" is not evidence it's gone); the renderer (`renderModelOptions`) appends a bare `<option>` for an uncovered saved model so the native select displays it (value-without-matching-option renders selectedIndex -1). Persisting (`changed:true`) only FILLS an EMPTY saved model: rec[0] in phase 1 when the catalog has entries, else live[0] in phase 2 after a SUCCESSFUL live fetch (`Array.isArray`) with entries, else it stays empty. An empty catalog no longer hard-disables the picker — the live fetch is still attempted; disabled only when both sources are empty and nothing is saved.
- **Live cache** — module-level `_liveModelsCache` keyed by provider (mirrors the existing `_catalogCache` pattern), invalidated + repopulated via `refreshProviderModels(provider, log)` whenever a key is saved or cleared, with a per-provider **epoch guard** (`_liveModelsEpoch`): `getLiveModels` captures the epoch at entry and only commits to the cache if it's unchanged after its awaits, and `invalidateLiveModels` bumps the epoch — so an in-flight fetch started with an old key that resolves AFTER "Remove key" cannot poison the cache. The key `<input>` persists "as typed" (every keystroke) — a naive invalidate-on-input would fire a live provider request per character, so the input path is debounced (`scheduleProviderModelsRefresh`, `BYOK_LIVE_REFRESH_DEBOUNCE_MS = 600`); the "Remove key" click is a deliberate one-shot action so it refreshes immediately and cancels any pending debounced timer. `cleanupByokTimers()` (exported) clears all pending debounce timers and is wired into `init.js cleanupAllConfigListeners` (TB rule 5, hot-reload).
- **Race guards** — a per-tier monotonic `_populateGeneration` counter is re-checked after EVERY await in `populateModelSelect` (after getCatalog, after getTierModel — i.e. immediately before the DOM clear — after the phase-1 persist, and after the live fetch): a slow OLDER call must never clear/re-render a NEWER provider/tier's select, in either phase.
- **Smoke parity (`byokSmoke.js`, same audit)**: the completion leg now sends the user's saved model VERBATIM whenever one is set (`model || interactiveModels[0]`) — the old `(model && interactiveModels.includes(model)) ? model : interactiveModels[0]` silently substituted a catalog model for live-only picks, so Test Connectivity never exercised the user's real model. The interactive catalog is only the fill-in when nothing is saved; it is NOT a gateway allow-list anymore.
