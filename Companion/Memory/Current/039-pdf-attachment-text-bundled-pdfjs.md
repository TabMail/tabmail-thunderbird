# PDF attachment text: the bundled pdf.js and what it needs

`attachment_read_pdf` (v1.9.0+, `chat/tools/attachment_read_pdf.js` → `chat/modules/pdfText.js`)
parses with pdf.js vendored under `chat/libs/pdfjs/` from the `pdfjs-dist` npm release, unmodified.
Facts measured while building it (2026-10-03, pdfjs-dist 6.3.289, Node 24):

- **Ship the LEGACY build.** The modern `build/pdf.min.mjs` calls `Uint8Array.prototype.toHex`,
  which Firefox ≥133 (so TB 145) has and Node 24 does not: every parse in Vitest fails with
  `n.toHex is not a function`. The legacy build runs in both, so the tests exercise the exact file
  the add-on ships. In Node it prints `@napi-rs/canvas` / `DOMMatrix` / `Path2D` warnings at import —
  rendering-only, harmless for text.
- **CMaps are required for CJK text.** A non-embedded Japanese font using the predefined
  `UniJIS-UCS2-H` CMap extracts as `""` without `cMapUrl`, and correctly with the bundled
  `cmaps/` (packed `.bcmap`, `cMapPacked: true`). `test/pdfText.test.js` pins this. In Node the CMap
  URL is a filesystem path; in the add-on it is `browser.runtime.getURL("chat/libs/pdfjs/cmaps/")`.
- **pdf.js drops text that runs off the page.** A 150-character single line on a 612pt page extracts
  as 81 characters. Test fixtures that need long pages must use several short lines.
- **Safety options**: `isEvalSupported: false` (no `new Function` font compilation; the add-on CSP
  forbids eval anyway), `enableXfa: false`, `disableFontFace: true`. PDF JavaScript only runs in the
  viewer's scripting sandbox (`pdf.sandbox.mjs`), which is not bundled (CVE-2026-16633 needed
  `enableScripting` in the viewer).
- **Parsing runs in pdf.js's own Worker** (`GlobalWorkerOptions.workerSrc` = bundled worker; CSP
  `worker-src 'self'`). The per-call deadline destroys the loading task, which terminates the worker;
  each call starts a fresh one.
- **Encryption**: a user password → `PasswordException` (refused); owner-password-only PDFs open and
  are read. Garbage, truncated and empty input → `InvalidPDFException`.
- **ID translation**: `idTranslator.processToolCallLLMtoTB` translates `unique_id` only for
  `email_*` tools plus an explicit `attachment_read_pdf` arm. A new tool that names an email by
  `unique_id` without the `email_` prefix needs its own arm, or it receives the model's number.

Test PDFs are generated by `test/helpers/pdfFixtures.js` (text, empty, image-only, CJK, RC4 rev 2
user/owner passwords); none are checked in.
