- **Single source of truth = `storage.local.autocompleteEnabled`** (default true). Read by THREE surfaces: the compose content script (`compose/compose-autocomplete.js initializeConfig` → `TM.state.autocompleteDisabled`), the Settings page (`config/modules/autocompleteSettings.js`), and the `change_setting` tool (key `compose.autocomplete_enabled` → storageKey `autocompleteEnabled`). All three round-trip via `storage.onChanged` so a change in any surface mirrors to the others (compose listener + `config/modules/init.js configStorageListener`).
- **Gate point for "off":** `core.js triggerCorrection` early-returns on `state.autocompleteDisabled` (the robust choke point — covers normal typing AND the `triggerInitialCorrection` runtime-message path which calls `triggerCorrection` directly); `events.js scheduleTrigger` also early-returns (avoids scheduling timers). Shared teardown/restore helpers live in `events.js`: `disableAutocompleteLocally()` (cancel idle timer, drop suggestion, `renderText(false)`, refresh banner to "off" — does NOT persist) and `enableAutocompleteLocally()` (refresh banner to "on" + **immediately re-fetch a suggestion** for the current editor text). The Shift+Esc handler AND the storage-listener branch both call these so behavior can't diverge. **Re-fetch on re-enable:** `enableAutocompleteLocally` resets the dedup markers (`originalText`/`lastSentLocalText`/`lastSentGlobalText` → null) so `triggerCorrection` isn't short-circuited by "text unchanged / already sent" (the user usually hasn't typed since toggling off), then fires `triggerCorrection(editorRef)` via a SINGLE reused `state.reenableFetchTimer` — because `storage.onChanged` fires in the SAME window that wrote it, the Shift+Esc path would otherwise schedule the fetch twice; the reused/cleared timer collapses it to one. Settings/tool re-enable reaches it via the compose storage-listener (one call, no direct path).
- **Shift+Esc REPURPOSED → autocomplete on/off TOGGLE (was toggle-diff-overlay):** `compose/modules/config.js keys.toggleDiffView` → renamed `keys.disableAutocomplete`; `events.js handleToggleDiffViewKey` → renamed `handleEscapeKeys`. Shift+Esc now TOGGLES: off→on or on→off, persisting `storage.local.autocompleteEnabled = !turningOff` (plain Esc = hide current suggestion, unchanged). The old diff-overlay toggle is GONE by design; `state.showDiff` is now effectively always true (the `showDiff===false` read in `caret.js:20` is now dead-but-harmless — `autoHideDiff`/`inlineEditActive` still drive caret-hint suppression). **Re-enable is discoverable from the compose window:** when OFF, the hints banner STAYS visible but switches to `"Autocomplete off · Shift+Esc to turn on"` (`caret.js _composeHintsBannerText()` branches on `state.autocompleteDisabled`; `showComposeHintsBanner` is now update-or-create/idempotent so the toggle refreshes text in place without flicker). Banner is only fully hidden when the "Show keyboard hints" appearance setting is off. (History: first implemented 2026-06-27 as a one-way "persistent kill-switch" with Settings-only re-enable; corrected same cycle to a two-way toggle per owner.)
- **Suggestion-delay control = `storage.local.AUTOCOMPLETE_IDLE_MS`** → `compose config autocompleteDelay.INITIAL_IDLE_MS` (NOT the deprecated/dead `TRIGGER_THROTTLE_MS`, which is loaded+stored but never consumed by the trigger logic — the real baseline is `currentIdleTime` seeded from `INITIAL_IDLE_MS`). `applyAutocompleteIdleMs()` sets INITIAL + scales `MAX_IDLE_MS = INITIAL+250` (preserves the 250ms back-off headroom) + resets `currentIdleTime` for immediate effect. Settings input `#autocomplete-delay` (0–3000ms, default 250).
- **Settings UI:** new `<section id="autocomplete-settings">` placed between Appearance and Notifications in `config.html` (checkbox `#autocomplete-enabled` + delay `#autocomplete-delay`), module `config/modules/autocompleteSettings.js` wired into `init.js` (import + change handler + load batch + storage-sync). The pre-existing `#compose-settings` debug-only section (`trigger-delay`/`diff-restore-delay`) is untouched and still hidden.
- **Banner (`caret.js showComposeHintsBanner`)** now renders an inner pill `<span>` with a SEMI-TRANSPARENT backdrop so the hint is legible: palette vars `--tm-hint-banner-bg`/`--tm-hint-banner-border` (added to BOTH light+dark blocks in `theme/palette/palette.build.js`, literal rgba like the sibling `--tm-hint-*`; no data.json change), and `--tm-hint-banner-text` darkened for contrast. Text now ends with `· Shift+Esc to turn off autocomplete`. Banner also gates on `state.autocompleteDisabled` (hidden when off). **Kept in lockstep:** `compose/background.js stripComposeHintsBannerFromText` bannerMac/bannerNonMac strings must match the new text (id-regex is primary, strings are the copy/paste fallback).
- **Versioning:** new `change_setting-v1.6.8.json` (loader picks highest schema ≤ client version, so only ≥1.6.8 clients see `compose.autocomplete_enabled`); `manifest.json` bumped 1.6.7 → **1.6.8** so the shipping client matches. Ran `gen:registries`. Tests: `chatTools.test.js` (autocomplete_enabled writes `autocompleteEnabled`, string coercion) + `composeConfig.test.js` (`keys.disableAutocomplete`). Intentionally TB-specific — iOS has no equivalent compose-autocomplete surface, so NOT added to iOS `change_setting`.
