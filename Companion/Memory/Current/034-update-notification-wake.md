# Update notification wake and state

`tmUpdates.onNotificationAction` is a persistent experiment event. A bar button can wake a suspended background, whose `updates/background.js` listener is registered synchronously at startup. The relay may still be present for other features; a real helper-off, relay-off Beta trial is required before counting this as a live wake pass.

The visible update bar is shared by TabMail add-on updates and the native FTS helper's restart prompt. The experiment keeps the add-on pending version in a **separate process-lifetime variable** that only the add-on update manager sets or clears. `showUpdateBar` changes the visible bar, not that add-on state. A background restart reads it through `getPendingUpdateVersion`; Thunderbird restart or true extension shutdown clears it. `hideUpdateBar` hides the bar for Later and the debug controls and leaves the add-on version alone; only the explicit debug clear command also calls `clearPendingUpdateVersion`. Do not replace the parent state with background module memory or persistent storage: the former disappears on suspend, while the latter survives an app restart that applies the update.

The debug simulator sends `setPendingUpdate` through the same manager as the popup. Its "Show Update Bar" button alone does not establish an add-on update. Live tests must use Thunderbird Beta on the designated test profile, fully cold-boot after parent-script edits, suppress the relay and native helper only in a private diagnostic package, and observe a real context close before the first button click. Do not click the live Restart button during a synthetic trial.
