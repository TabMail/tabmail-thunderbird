# Device Sync local edits after background suspension

The parent WebSocket surviving suspension does not preserve the background storage-change listener. Register `setupStorageListener()` synchronously during background evaluation; late initialization remains an idempotent retry. A first local template edit can otherwise wake the background through another listener without receiving a sync timestamp or broadcast. Reconnecting to an already-open parent socket does not reconstruct that missed timestamp.

The listener records local timestamps even while auto-sync is paused; pausing transport must not make a newer edit look stale when sync resumes. Remote-echo suppression is checked synchronously. The broadcast debounce does not reconnect an explicitly paused transport. Bundled prompt getters return defaults without persisting them as edits, so a fresh profile cannot timestamp and broadcast defaults over peer customizations. If late startup has not yet attached module state to the existing parent transport, the debounce connects before broadcasting. Registration ownership is assigned only after successful addListener so a failed registration can retry.

`deviceSyncLocalWake.test.js` executes the real listener and its early registration while startup awaits, using synthetic storage and transport. Additional cases run initialization through the real KB reminder generator and prompt getter with asynchronous storage events, then verify a synthetic peer retains its custom KB. Paused-edit cases verify timestamp/history retention and peer merge effects after resume. Live suspend/wake validation can namespace the test keys and capture outbound sends; that validates local delivery and timestamp/broadcast effects, but does not prove remote peer convergence.
