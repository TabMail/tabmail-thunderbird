# Action mutations have one owner

Status: implemented, 2026-09-12.

`agent/modules/actionCache.js` owns action payload and metadata writes, removals, and full-cache wipes. Every payload mutation runs on its serial queue: resolve exact-folder message identities, commit IDB, project the new action (empty string for removal) to all matching native headers, await chip refresh, then schedule sorting if the payload value changed. Metadata touches do not repaint or restart sorting. The existing trailing-edge 30-second sort policy remains separate from painting. Native projection invalidates each owning thread tree with `invalidateRow` (or `invalidate` after a bulk write); `nsIMsgDBView.NoteChange` is not exposed to JavaScript.

Automatic work carries an in-memory token owned by its caller or queue item. Ordinary retries and merges retain it; explicit recompute starts new work, and older completions cannot remove that newer request. Matching manual mutations invalidate active tokens; completion releases them, so no permanent per-message generation history is retained. A completed action-only clear or full wipe invalidates all earlier tokens, including work without a cached row. Full privacy wipes call the serialized storage clear directly, without inventory or repaint prerequisites; any stale native tint recovers on reload. Recovered queue items with a different live key are discarded before processing; fresh current-identity work remains eligible. Thread-effective writes derive from current member actions inside the same mutation queue, so callers never replay captured classifications. Internal-message processing retains the existing aggregation follow-up after committing its action. Generated values are restricted to the existing action priority list before voting; unsupported output follows the existing retryable failure path.

Action payloads and painters are inbox-scoped. Clears can remove stale projections outside inboxes. Unknown folder inventory is not deletion evidence. Startup and account/folder creation backfill both present and absent canonical actions using the listed message IDs without per-message folder rescans. Optional tag-definition setup failures do not block core startup. Projection failure preserves canonical state and does not schedule autonomous account scans; subsequent direct projection or reload provides recovery. Only startup requests immediate sorting. Suspend invalidates active work and removes creation listeners.

Legacy IMAP action keywords no longer supply painter state. Native tag definitions remain available for action colors. Table self-healing covers the entire rendered pool; card teardown respects the installed wrapper's owner.

Validation is recorded in `TESTS.md`. The native projection is a render cache; IDB remains canonical.
